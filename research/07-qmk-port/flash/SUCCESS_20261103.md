# QMK and VIA physical result

The user subsequently confirmed: “is working now.” This is user-reported
functional confirmation; the exact keys and power/suspend scenarios tested
were not specified. The complete method and experiment chronology are in
[the reverse-engineering guide](../../../docs/history/REVERSE_ENGINEERING_GUIDE.md).

The diagnostic V2 image is installed and enumerating as the expected QMK
keyboard plus VIA Raw HID interface (`3532:a0a3`). No stock rollback was
performed after this successful trial.

- VIA ELF SHA256: `8409b03b951c6ca168efff46d750dfd7d9f8ea6a599a39c0a19cfb1c4b36b0c9`.
- Application body SHA256: `d5979751baa00152980f1b4c461737ae49ed5788b85dc4167d1f2a1cc6d3dea6`.
- All117 application pages passed full readback verification. Bootloader,
  outside-application flash and hidden metadata matched the same-session backup.
- Read-only VIA queries returned protocol13, three layers and expected keycode.
- QMK identity and repeated VIA replies stayed available throughout a15-second
  observation, beyond the diagnostic deadline window.
- A VIA remap in physically absent slot layer2/row5/column0 was written, read
  back and restored to its original value0. No flash writes were involved.

Evidence: `live_qmk_20261103T075452_444196Z/result.json`,
`via_live_queries.json`, `runtime_soak.json`, and `via_live_remap.json`.

The preceding diagnostic V1 trial reached the main loop, counted5000 SysTicks,
recorded one auxiliary IRQ and no primary USB events, then automatically
returned to bootloader. Its trace was read and stock restored without physical
reconnection. That trace is in
`live_rollback_20261103T073830_059181Z/diagnostic_trace.json`.

V2 then added the original shared startup sequence and the missing auxiliary
bit7 acknowledgement. Both were checked against original instructions. Their
combined change resolved enumeration in this trial; no separate experiment
identifies which change was necessary or sufficient.

This remains diagnostic firmware. It records runtime state in RAM and requests
the bootloader if USB is unconfigured after5000 SysTicks, or on a captured
NMI/HardFault. The native timed-resume branch is not fully implemented. VIA
configuration is RAM-only and disappears on reset/power loss. User-confirmed
operation does not establish complete all-key behavior, true cold-power startup,
or suspend/resume validation. Do not label this production-ready firmware.
