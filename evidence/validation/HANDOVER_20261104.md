## Open problem (blocks capture-free flashing)
Two hardware tests with the authored loader+header: **every even program word
stays erased (FF), odd words correct**; erase works. Adding a 130-cycle delay
before start did not help. Emulator can't see it (skips crypto setup `0x398`
and timing). Prime suspect: **plaintext header mode** (vendor header runs the
AES engine at 0x4000D000 / `0x398`, mine doesn't).
Next experiment, ready in `scratchpad/flash_authored_test.py`:
- arg 3 `vendor-header` → authored loader + vendor header
- arg 3 `vendor-loader` → vendor loader + authored header
Whichever fails identifies the culprit. Needs one Esc+replug per test, then
restore as above. Do **not** make `authored` the release default until a
hardware flash passes.
